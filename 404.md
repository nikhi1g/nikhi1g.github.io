# 404 dot — life cycle plan

Checklist for the status dot on [404.html](404.html). The creature feature is
complete and verified in a real browser against the implementation; every item
below is shipped.

## Already shipped

- [x] Physics uses a 100 px/m scale with `g = 981 px/s²` in [404/js/physics.js](404/js/physics.js).
- [x] Bounce and slide use restitution `0.58`, wall restitution `0.4`, linear air drag `0.3`, and rolling resistance once the user is in charge.
- [x] Sleep thresholds end micro-bounces and creeping rolls (`vx === 0 && vy === 0` counts as asleep).
- [x] Integration runs on a fixed `1/240 s` timestep with an accumulator, so bounces stay stable at any frame rate.
- [x] A swept floor test means the footer rule only catches a dot that was above it.
- [x] The footer rule is a floor over its own x-span and the card bottom is the floor elsewhere, so the dot rolls off the rule's edge on a proper projectile arc.
- [x] One random rightward shove per load (`rollVector`) with drag scaled to it is the only self-propelled motion.
- [x] The first `pointerdown` clears the load shove forever, after which the dot goes only where it is thrown and can be rested on the rule.
- [x] The dot is draggable and throwable, with the release velocity clamped so a fast flick stays on screen.
- [x] The ball-state eye (`.eye` > `.pupil`) appears only when the dot is fully asleep, scaling in with overshoot.
- [x] The ball-state pupil tracks the cursor within a 1.5 px reach, and the rig's iris takes over tracking once sprouted ([404/js/figure.js](404/js/figure.js)).
- [x] Blinking runs on a random 2.6–6.4 s cadence with a 25% chance of a double blink.
- [x] The eye closes the moment the dot is in motion again.

## The idea

- [x] The ball is the creature's "curled up" state, and it sprouts into a small stick figure when left at rest.
- [x] Any disturbance — drag, throw, any motion — snaps the figure straight back to a ball.
- [x] Left alone long enough, the figure gets bored and starts chopping the page apart with a little axe, then puts it back together with a hammer.
- [x] It dodges the cursor the whole time — actively dodging close approaches; near misses now trigger immediate flee ~82% of the time with a ~0.9 s cooldown.

## States

- [x] `ball`: any motion (`vx !== 0 || vy !== 0`) or dragging shows the plain dot with no features.
- [x] `resting`: physics asleep shows the dot plus the tracking, blinking eye.
- [x] `sprouted`: asleep for ~1.2 s shows the stick figure with eye tracking.
- [x] `sprouted` has an idle bob once idle life lands (2.6 s breathing on `#torso` with a lagging `#hair` counter-bob).
- [x] `walking`: after ~6 s idle, the figure walks along its current surface.
- [x] `chopping`: on reaching a target element, the figure swings its axe and the target degrades.
- [x] `rebuilding`: once everything is fully broken or after ~20 s of chopping, the figure reverses the damage with its hammer.
- [x] `fleeing`: with the cursor within ~90 px, a ~50% roll (rate-limited to once per ~2.5 s) makes the figure drop its tool and run/jump away.
- [x] Any physics wake-up (drag, throw, or the surface disappearing under the dot) collapses whatever is happening straight back to `ball`.
- [x] Any wake-up aborts everything in flight via a generation counter in [404/js/creature.js](404/js/creature.js).
- [x] The creature keeps a skip-set for unreachable targets so it never spins, walking via `dot.onStep` polling and peering/hopping at surface ends.

## Sprout animation

- [x] The rig unfolds ~1.2 s after the dot settles (`sproutTimer` in [404/js/figure.js](404/js/figure.js)).
- [x] Each joint group (`.joint`) scales from its own pivot, so limbs unfold out of the body instead of appearing.
- [x] The pop is bottom-up and staggered: legs, then arms, then hair (transition delays in [404/css/figure.css](404/css/figure.css)).
- [x] Sprouting uses an overshoot curve (`cubic-bezier(0.34, 1.56, 0.64, 1)`) and collapse is faster, limbs retracting before the body rounds back to a ball.
- [x] Any motion collapses the figure: the sleep-change handler removes `.sprouted` (and `.blinking`) immediately.
- [x] `prefers-reduced-motion` gets the quiet path: no sprout animation, no bob, no walking, no chopping, no rebuild (`start()` in [404/js/creature.js](404/js/creature.js) is a no-op).

## Figure rig (from the reference drawing)

- [x] The rig is a stroke-based SVG (`.figure` inside `.dot` in [404.html](404.html)), crisp at any size.
- [x] The ball is the head: a cyclops whose `.skull` keeps the dot's `--acc` blue and whose `.sclera` + `.iris` keep the single eye.
- [x] The rig's head renders at exactly the ball's 16 px, so sprouting has no size jump ([404/css/figure.css](404/css/figure.css)).
- [x] `#hair` is three bars off the crown, splayed and slightly curved with rounded caps.
- [x] `#torso` is one straight vertical bar below the head, with no joint.
- [x] `#arm-l` / `#arm-r` leave the upper torso swept down and out, gently curved with no elbow and rounded caps.
- [x] `#leg-l` / `#leg-r` are jointed bars from the torso's base, each ending in a small angled foot.
- [x] Limbs and hair use the light stroke colour (`--fg` via `.bone`), so they read against both themes.
- [x] The ball-state `.eye` is `display: none` while sprouted, so only the rig's eye shows and no stray eye sits at the figure's feet.
- [x] Sprouted gaze is computed from the untransformed `.skull` rect with a runtime viewBox scale factor and mirrored-X handling, so tracking is linear and symmetric with no accumulated drift; collapse clears the blink class and all inline eye transforms.

## Walking

- [x] Walking surfaces are the ones physics already knows: the footer rule's span and the card bottom.
- [x] Walking is clamped by predicting the next step against the current surface span, since physics exposes no position setter.
- [x] Gait is a leg-swing animation in [404/js/gait.js](404/js/gait.js) driven off the same rAF loop as the physics, walking at ~40 px/s via `dot.drive()` rather than through the force integrator.
- [x] At the end of the rule the figure stops, peers over the edge, and either turns around or deliberately hops down.
- [x] The hop is a real physics impulse — `dot.hop(260, dir*55)` with the tuck class cleared once `dot.isGrounded()` — so the arc matches the rest of the simulation.
- [x] Physics exposes the walk/hop/debris API — `drive`, `release`, `hop`, `world`, `pos`, `velocity`, `surface`, `isGrounded`, `onStep`, `spawnDebris`, `clearDebris`, `radius` — in [404/js/physics.js](404/js/physics.js).
- [x] `asleep` survives a driven walk, so the figure stays sprouted while walking.

## Chopping

- [x] Targets include major copy and chrome: `main`, `h1`, `.message h2`, `.message p`, `#version`, `#theme-toggle`, `.hint`, `.hint kbd`, `#inquiry-email`, `footer`, `footer span`.
- [x] A chop cycle walks to the target's x-position, swings the axe ~3 times, then applies one stage of damage.
- [x] Damage stages per target (`dmg-tilt`, `dmg-crack`, `dmg-split`/`dmg-dim`, plus text-stage variants) are CSS-driven and recorded in a strict global LIFO log.
- [x] Visible damage still replays on a strict LIFO class log; torn chunks are cloned and animated via the physics debris integrator, then removed cleanly on rebuild.
- [x] Damage keeps the page readable and the keypress return-home interaction intact at all times.
- [x] Chopped letters and non-letter fragments become physical debris clones handed to `dot.spawnDebris()`, falling with the same gravity/restitution onto the rule or card floor (undo removes the clone and restores the original text/class state).
- [x] `#axe` and `#hammer` SVG groups live inside `#arm-r` in [404.html](404.html), and [404/css/tools.css](404/css/tools.css) hides both by default, showing exactly the held one only while `sprouted`, with an extra blade whip on the axe swing and a reduced-motion block.

## Cursor avoidance

- [x] Within ~130 px the figure aggressively flees; very-close approaches are nearly guaranteed and normal avoidance is about 82% with a tighter ~0.9 s cooldown.
- [x] Between ~130 px and ~190 px it keeps working but tracks the cursor and leans away, with near approaches triggering immediate escapes.
- [x] Clicking or poking the figure never navigates home (there is no document click handler in [404/js/return-home.js](404/js/return-home.js) — clicks simply never navigate), and the figure stays grabbable via its own pointer handling.
- [x] Fleeing never overrides the keypress-to-go-home escape — no figure movement can block a keypress.
- [x] The document-level click-to-leave handler was deliberately removed so clicks and drags belong to the figure.

## Architecture

`404.html` is a thin shell — markup plus six stylesheet links and one module script.
GitHub Pages only serves `/404.html`, so the shell has to stay at the repo root; every
component lives in `404/` and is copied into `_site` by
[.github/scripts/build-site.mjs](.github/scripts/build-site.mjs).

| file | owns |
|---|---|
| [404/css/base.css](404/css/base.css) | theme tokens, body, card, header, type, links, footer |
| [404/css/interaction.css](404/css/interaction.css) | copy toast, commit span, hint line, leave animation |
| [404/css/figure.css](404/css/figure.css) | dot, SVG rig, joints, eye, blink, sprout |
| [404/css/gait.css](404/css/gait.css) | idle bob, 0.7 s walk cycle, face-left mirror, peer/hop/lean/swing poses, reduced-motion block |
| [404/css/tools.css](404/css/tools.css) | `#axe`/`#hammer` visibility (held one only while sprouted), axe blade whip, reduced-motion block |
| [404/css/damage.css](404/css/damage.css) | damage stages, `.letter`/`.letter-gone`/`.letter-debris`, transitions, reduced-motion block |
| [404/js/theme.js](404/js/theme.js) | `initTheme()` — dark/light toggle and persistence |
| [404/js/clipboard.js](404/js/clipboard.js) | `initClipboard()` — copy toast, email/commit/version copy |
| [404/js/return-home.js](404/js/return-home.js) | `initReturnHome()` — key-only to leave (plus `.hint` link) |
| [404/js/version.js](404/js/version.js) | `initVersionWatcher()` — `commit.json` polling |
| [404/js/physics.js](404/js/physics.js) | `createDot()` — the whole simulation plus the walk/hop/debris API (`drive`/`release`/`hop`/`onStep`/`spawnDebris`) |
| [404/js/figure.js](404/js/figure.js) | `initFigure(dot)` — eye, blinking, sprout/collapse |
| [404/js/gait.js](404/js/gait.js) | `createGait(dot)` — facing, idle, 40 px/s walk with edge prediction, lean, peer, hop-down, swing |
| [404/js/damage.js](404/js/damage.js) | `createDamage(dot)` — break/fix targets, stage classes, strict LIFO log, falling-letter debris |
| [404/js/creature.js](404/js/creature.js) | `createCreature({dot, gait, damage})` — rest/work/rebuild state machine, skip-set, flee/lean, generation counter, reduced-motion no-op |
| [404/js/main.js](404/js/main.js) | wiring gait/damage/creature, nothing else |

- [x] Modules share no globals; [404/js/main.js](404/js/main.js) only wires `createDot()` into `initFigure(dot)` plus `gait`/`damage`/`creature`.
- [x] The cross-module contract is what `createDot()` returns, now extended with the walk/hop/debris API: `drive`, `release`, `hop`, `world`, `pos`, `velocity`, `surface`, `isGrounded`, `onStep`, `spawnDebris`, `clearDebris`, `radius`.
- [x] Physics owns motion and the `asleep` class and knows nothing about eyes, limbs, or blinking; the creature subscribes to `onSleepChange` and owns everything expressive.
- [x] Each new behaviour (walking, axe, damage log, rebuild) ships as its own module behind that same contract — `gait`, `damage`, and `creature` all build on `createDot()` without touching each other's files.

## Constraints

- [x] No dependencies, no bundler, no build step beyond the existing copy script — plain CSS and ES modules.
- [x] All motion is CSS/SVG transforms plus the existing rAF loop — no canvas, no WebGL.
- [x] The rig is stroke-based SVG so it stays crisp at any size; no scaled-up raster or sub-pixel CSS box fakes size.
- [x] The page stays a working 404 first: press any key returns home (plus a direct click on the `.hint` link), and theme toggle, commit copy, and email copy keep working untouched.

## Build order

- [x] 1. Sprout/collapse animation only — limbs, pop, reverse, reduced-motion path.
- [x] 2. Idle life: bob, weight shift, occasional look-around.
- [x] 3. Walking along both surfaces, plus the hop between them.
- [x] 4. Cursor avoidance.
- [x] 5. Axe and the reversible damage log.
- [x] 6. Rebuild pass.
