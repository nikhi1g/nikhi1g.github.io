# 404 dot — life cycle plan

Checklist for the status dot on [404.html](404.html). Ticked items are shipped and
verified against the implementation; unticked items are still to build. The reference
drawing has landed and the rig is built from it.

## Already shipped

- [x] Physics uses a 100 px/m scale with `g = 981 px/s²` in [404/js/physics.js](404/js/physics.js).
- [x] Bounce and slide use restitution `0.58`, wall restitution `0.4`, linear air drag `0.3`, and rolling resistance once the user is in charge.
- [x] Sleep thresholds end micro-bounces and creeping rolls (`vx === 0 && vy === 0` counts as asleep).
- [x] Integration runs on a fixed `1/240 s` timestep with an accumulator, so bounces stay stable at any frame rate.
- [x] A swept floor test means the footer rule only catches a dot that was above it.
- [x] The footer rule is a floor over its own x-span and the card bottom is the floor elsewhere, so the dot rolls off the rule's edge on a proper projectile arc.
- [x] One random rightward shove per load (`rollVector`) with drag scaled to it is the only self-propelled motion.
- [x] The first `pointerdown` clears the load shove forever, after which the dot goes only where it is thrown and can be rested on the rule.
- [x] The dot is draggable and throwable, with the release velocity clamped so a fast flick stays on screen.
- [x] The ball-state eye (`.eye` > `.pupil`) appears only when the dot is fully asleep, scaling in with overshoot.
- [x] The ball-state pupil tracks the cursor within a 1.5 px reach, and the rig's iris takes over tracking once sprouted ([404/js/figure.js](404/js/figure.js)).
- [x] Blinking runs on a random 2.6–6.4 s cadence with a 25% chance of a double blink.
- [x] The eye closes the moment the dot is in motion again.

## The idea

- [x] The ball is the creature's "curled up" state, and it sprouts into a small stick figure when left at rest.
- [x] Any disturbance — drag, throw, any motion — snaps the figure straight back to a ball.
- [ ] Left alone long enough, the figure gets bored and starts chopping the page apart with a little axe, then puts it back together.
- [ ] It avoids the cursor the whole time.

## States

- [x] `ball`: any motion (`vx !== 0 || vy !== 0`) or dragging shows the plain dot with no features.
- [x] `resting`: physics asleep shows the dot plus the tracking, blinking eye.
- [x] `sprouted`: asleep for ~1.2 s shows the stick figure with eye tracking.
- [ ] `sprouted` gains an idle bob once idle life lands.
- [ ] `walking`: after ~6 s idle, the figure walks along its current surface.
- [ ] `chopping`: on reaching a target element, the figure swings its axe and the target degrades.
- [ ] `rebuilding`: after enough damage, or ~20 s of chopping, the figure reverses the damage.
- [ ] `fleeing`: with the cursor within ~90 px, the figure drops the axe and runs/jumps away.
- [x] Any physics wake-up (drag, throw, or the surface disappearing under the dot) collapses whatever is happening straight back to `ball`.

## Sprout animation

- [x] The rig unfolds ~1.2 s after the dot settles (`sproutTimer` in [404/js/figure.js](404/js/figure.js)).
- [x] Each joint group (`.joint`) scales from its own pivot, so limbs unfold out of the body instead of appearing.
- [x] The pop is bottom-up and staggered: legs, then arms, then hair (transition delays in [404/css/figure.css](404/css/figure.css)).
- [x] Sprouting uses an overshoot curve (`cubic-bezier(0.34, 1.56, 0.64, 1)`) and collapse is faster, limbs retracting before the body rounds back to a ball.
- [x] Any motion collapses the figure: the sleep-change handler removes `.sprouted` (and `.blinking`) immediately.
- [x] `prefers-reduced-motion` gets the quiet path: no sprout animation, no bob, no walking, no chopping.

## Figure rig (from the reference drawing)

- [x] The rig is a stroke-based SVG (`.figure` inside `.dot` in [404.html](404.html)), crisp at any size.
- [x] The ball is the head: a cyclops whose `.skull` keeps the dot's `--acc` blue and whose `.sclera` + `.iris` keep the single eye.
- [x] The rig's head renders at exactly the ball's 16 px, so sprouting has no size jump ([404/css/figure.css](404/css/figure.css)).
- [x] `#hair` is three bars off the crown, splayed and slightly curved with rounded caps.
- [x] `#torso` is one straight vertical bar below the head, with no joint.
- [x] `#arm-l` / `#arm-r` leave the upper torso swept down and out, gently curved with no elbow and rounded caps.
- [x] `#leg-l` / `#leg-r` are jointed bars from the torso's base, each ending in a small angled foot.
- [x] Limbs and hair use the light stroke colour (`--fg` via `.bone`), so they read against both themes.
- [x] The ball-state `.eye` fades out while sprouted so only the rig's eye shows.

## Walking

- [ ] Walking surfaces are the ones physics already knows: the footer rule's span and the card bottom.
- [ ] Walking is clamped to the current surface's x-range.
- [ ] Gait is a leg-swing animation driven off the same rAF loop as the physics, with `vx` set directly (~40 px/s) rather than through the force integrator.
- [ ] At the end of the rule the figure stops, peers over the edge, and either turns around or deliberately hops down.
- [ ] The hop is a real physics impulse — `vy` set negative, control handed back to the integrator, so the arc matches the rest of the simulation.

## Chopping

- [ ] Targets are real elements: the `h1`, the `.message` heading and paragraph, the `.hint` kbd, the footer rule, the footer text.
- [ ] A chop cycle walks to the target's x-position, swings the axe ~3 times, then applies one stage of damage.
- [ ] Damage stages per target (letters dropping off the heading, the rule splitting, the kbd border cracking) are CSS-driven and recorded in a log.
- [ ] Nothing leaves the DOM — damage is class-based and fully reversible, so rebuilding replays the log backwards.
- [ ] Damage keeps the page readable and the keypress return-home interaction intact at all times.
- [ ] Chopped letters that fall become physics bodies using the same integrator, landing on the rule or the floor.

## Cursor avoidance

- [ ] Within ~90 px the figure enters `fleeing`: it runs away along the surface, jumping the gap to the other surface if cornered.
- [ ] Between ~90 px and ~180 px it keeps working but watches the cursor — eye tracking plus a body lean away from it.
- [x] Clicking or poking the figure never navigates home (there is no document click handler in [404/js/return-home.js](404/js/return-home.js) — clicks simply never navigate), and the figure stays grabbable via its own pointer handling.
- [x] Fleeing never overrides the keypress-to-go-home escape — no figure movement can block a keypress.
- [x] The document-level click-to-leave handler was deliberately removed so clicks and drags belong to the figure.

## Architecture

`404.html` is a thin shell — markup plus three stylesheet links and one module script.
GitHub Pages only serves `/404.html`, so the shell has to stay at the repo root; every
component lives in `404/` and is copied into `_site` by
[.github/scripts/build-site.mjs](.github/scripts/build-site.mjs).

| file | owns |
|---|---|
| [404/css/base.css](404/css/base.css) | theme tokens, body, card, header, type, links, footer |
| [404/css/interaction.css](404/css/interaction.css) | copy toast, commit span, hint line, leave animation |
| [404/css/figure.css](404/css/figure.css) | dot, SVG rig, joints, eye, blink, sprout |
| [404/js/theme.js](404/js/theme.js) | `initTheme()` — dark/light toggle and persistence |
| [404/js/clipboard.js](404/js/clipboard.js) | `initClipboard()` — copy toast, email/commit/version copy |
| [404/js/return-home.js](404/js/return-home.js) | `initReturnHome()` — key-only to leave (plus `.hint` link) |
| [404/js/version.js](404/js/version.js) | `initVersionWatcher()` — `commit.json` polling |
| [404/js/physics.js](404/js/physics.js) | `createDot()` — the whole simulation |
| [404/js/figure.js](404/js/figure.js) | `initFigure(dot)` — eye, blinking, sprout/collapse |
| [404/js/main.js](404/js/main.js) | wiring, nothing else |

- [x] Modules share no globals; [404/js/main.js](404/js/main.js) only wires `createDot()` into `initFigure(dot)`.
- [x] The only cross-module contract is what `createDot()` returns: `{ el, start(), onSleepChange(fn), isAsleep(), isDragging() }`.
- [x] Physics owns motion and the `asleep` class and knows nothing about eyes, limbs, or blinking; the creature subscribes to `onSleepChange` and owns everything expressive.
- [ ] Each new behaviour (walking, axe, damage log, rebuild) ships as its own module behind that same contract, so phases can be built in parallel without touching each other's files.

## Constraints

- [x] No dependencies, no bundler, no build step beyond the existing copy script — plain CSS and ES modules.
- [x] All motion is CSS/SVG transforms plus the existing rAF loop — no canvas, no WebGL.
- [x] The rig is stroke-based SVG so it stays crisp at any size; no scaled-up raster or sub-pixel CSS box fakes size.
- [x] The page stays a working 404 first: press any key returns home (plus a direct click on the `.hint` link), and theme toggle, commit copy, and email copy keep working untouched.

## Build order

- [x] 1. Sprout/collapse animation only — limbs, pop, reverse, reduced-motion path.
- [ ] 2. Idle life: bob, weight shift, occasional look-around.
- [ ] 3. Walking along both surfaces, plus the hop between them.
- [ ] 4. Cursor avoidance.
- [ ] 5. Axe and the reversible damage log.
- [ ] 6. Rebuild pass.
